# v2 clarifications (answers from the product owner)

Source spec: [`v2-product-context.md`](v2-product-context.md). These answers fill gaps in that spec and take precedence over it.

| # | Question | Answer |
|---|---|---|
| 1 | Do Admins also mark attendance and apply for leave? | **Yes.** Admins follow the same first-login attendance choice, logout and leave-request flow as Staff, and the CEO approves them. Admins can also be assigned tasks. |
| 2 | Which Admin does the Admin approval step? | **It depends on how the task was created.** Each task has an optional *approving Admin*. CEO assigns directly → no Admin step (Done → CEO approval only). CEO assigns through an Admin → the CEO picks the Admin, and the flow is Done → that Admin → CEO. Admin-created client task → the client's assigned Admin → CEO. Admin-created internal task → the creating Admin → CEO. The CEO can change or remove the approving Admin at any time. *This overrides v2 §20's "every task goes through Admin approval": the CEO step is always required, the Admin step only when the task has an approving Admin.* |
| 3 | What if the approving Admin is also an assignee? | **Skip the Admin step.** Nobody approves their own work. The task goes from Done straight to CEO approval, and the history records that the Admin step was skipped because the approver was an assignee. |
| 4 | Weekly offs and holidays? | **Company-wide days off.** The CEO sets the weekly off days (e.g. Sunday) and a holiday list in Settings. No automatic "Absent" flag on those days. A login on a day off still records attendance, marked "Worked on a day off" (useful for compensatory leave). No per-employee off days in the prototype. |
| 5 | Brand Kit or Google Drive link? | **A light Brand Kit plus the Drive link.** MaxOff stores the logo, colour codes, font names, tone of voice and brand notes. Full assets stay in Google Drive through the client's link. The logo shows in client lists. Staff see these brand basics (not the rest of the client record) on client-linked tasks. No bulk asset uploads or ZIP downloads. |
| 6 | What can an Admin see outside their own clients? | **Only their own.** An Admin sees their assigned clients (and those clients' monthly work, projects and tasks), plus tasks they created, are the approving Admin for, or are assigned to. For everything else they see only **availability**: a person's task count, busy calendar blocks and approved leave, without details. This is enough for workload and conflict warnings. |
| 7 | What is an Additional Work item? | ⚠️ *Superseded by #8: Additional Work is now a one-time client project.* Original answer: **A task classified as Additional Work.** It must be linked to a client and can have an optional billable amount only the CEO sees. Several steps go in the task's optional stages or subtasks. Normal approval chain; revenue counts after CEO approval. "Staff request additional work" = Staff *suggest* a task (a task request), which CEO/Admin approves and turns into a real task. |
| 8 | How do Monthly Work, Projects and Tasks relate? | **Two separate systems** (this replaces v2 §26–35 Monthly Scope / Monthly Deliverables / Additional Work as separate concepts). **(a) Client work:** Client → Projects → project items ("tasks"). A project is **one-time, weekly or monthly**. The Admin names each item (e.g. "Reel 1 – Ambience", "Week 1 drone documentation") and ticks it done. Extra/additional work = a one-time project, often with a single item. **(b) Staff work:** daily tasks allotted to people, with acknowledgement, comments, Done and the approval chain (#1–3). Staff tasks are **not connected to client projects**, and Staff never see client progress. The Admin tracks both systems. |

## Follow-up questions opened by #8
- 8a. Do staff tasks show a client name at all? → **Yes, an optional client label.** Staff see the client's name and brand basics (#5) on the task, and nothing else about the client. The label does **not** link the task to any client project or item. Admins see staff tasks labelled with their clients (fits #6).
- 8b. Who has the final say on a project item? → **The Admin ticks, then the CEO approves.** Admin tick = done operationally. CEO approval = final and revenue-eligible. Individual or bulk approval (each item still gets its own approval record). Reports show both counts, e.g. "9/12 done · 8/12 CEO-approved". The CEO can reject with a reason, which sends the item back to the Admin.
- 8c. Do project items have stages? → **Optional stages, set per project.** The Admin picks a stage list (or none) when creating a project, e.g. Script → Shoot → Edit → Posted. All items in the project get those stages and the Admin ticks them. The item's Done tick is separate and still needs CEO approval (8b). Stage lists are reusable presets in Settings (data, not code).
- 8d. New week/month on a recurring project? → **Automatic new cycle.** At 12:00 AM IST on the 1st (monthly) or Monday (weekly), for active clients only, MaxOff creates the new cycle and copies the project's item list. The Admin renames items with that period's themes. Unfinished items from the previous cycle are highlighted, and the **CEO** decides each one: carry forward / close / leave pending. Carried items keep their original period (they don't inflate the new cycle's scope or planned revenue). Each cycle is its own reporting and revenue period. Paused clients get no new cycles. Admin/CEO can start a cycle manually.
- 8e. How are the billing categories told apart? → **The CEO sets a billing category on each project:** Retainer / Project / Additional Work. It defaults from recurrence (monthly/weekly → Retainer, one-time → Project) and only the CEO can change it. CEO-only amounts: per cycle (a total split evenly across items, or per-item values) or per one-time project (fixed or per item). Revenue counts item by item after CEO approval (8b). CEO overrides are stored next to the system-calculated value. Reports split totals by category (v2 §36–41, adapted to projects).

| 9 | What happens when the CEO rejects attendance? | **The CEO sets the correct status, with a reason.** When rejecting, the CEO picks what the day actually was (Absent / Leave / Half-Day Leave / Compensatory Leave / Present) and gives a reason. The employee is notified. The original submission and the correction both stay in the history. The same applies to leave chosen at login. |
