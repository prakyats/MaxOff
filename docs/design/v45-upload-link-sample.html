v4.5 Upload link: screens to approve

A private link per task. Anyone holding it can send files straight into the studio's Google Drive, into that task's folder, with no login. Files go from their browser to Google directly, never through MaxOff. This sample shows what the person with the link sees (on a phone and on a laptop) and what the Admin sees on the task while files arrive. Nothing is built yet. Example names (Sam, Alex, Jordan, "Brand reel", "Example Café") are made up.

Questions for the owner

The decisions (issue #89, 14 Nov) leave these open. Each one shows my recommendation first; the screens below are drawn with it. Reply with the numbers you want changed.

  1. Who can make, copy and stop a task's link? Decided (owner, 19 Nov): only the Owner and the task's Admin. Crew on the task don't see the link.
  2. Which tasks can have a link? Recommend: any task with a client or without. The Admin taps Get upload link on the task when it's needed. No new setting. Or: only task types you switch on in Settings (for example a "Shoot" type).
  3. Reaching an uploader who is stuck. Decided (owner, 19 Nov): no phone number field and no Call or WhatsApp anywhere. The page asks for a name only, and the stuck alert just says who is stuck.
  4. "Coming back later shows what's done" against "the link never lists files". Recommend: a returning uploader sees only the files they sent from that same phone or laptop (MaxOff remembers the device). They never see another uploader's files, and someone who only has the link sees no file names at all. Files already sent are skipped by name and size, checked against that uploader's own files. Or: anyone with the link sees every file sent so far (this makes a forwarded link show the whole shoot).
  5. What the page shows about the task. Recommend: the studio's name and the task's title only ("Brand reel"). No client name, deadline, people or folder. A link that gets forwarded then gives little away. Or: also show the client's name.
  6. How the Admin opens the folder. Decided (owner, 19 Nov): no sharing per folder. The Admins already use the studio's Drive account, so "Open the folder in Drive" simply links to the task folder.
  7. Removing an unwanted file (a wrong clip, a stranger's upload). Recommend: the task's Admin or the Owner taps Remove on the file and gives a reason. MaxOff moves it to the Drive bin (Google keeps it 30 days) and keeps the row in the task's history. Never a permanent delete. Or: only the Owner can remove files.
  8. Tapping "All files received" while a file is still uploading. Recommend: the sheet says "1 file is still uploading from Sam" and still allows it. A file already started can't be stopped on Google's side; if it finishes, it is kept and marked "arrived after the link stopped". Or: the button waits until nothing is uploading.
  9. After the link is stopped (Stop link, or All files received). Recommend: the Admin can tap Make a new link. The old one never works again, and the files stay where they are. Or: one link per task for its whole life; once stopped, there is no new one. Also: when the primary marks the task Done the link stops. If the task is then sent back, recommend the link stays stopped and the Admin makes a new one if more files are needed.
  10. Google's own daily limit. A personal Google account accepts about 750 GB of uploads a day. A big day of shoots can reach it. Recommend: uploads pause with "The studio's Drive has reached Google's daily upload limit. Keep this page open; it carries on by itself when Google allows it." The Owner and the task's Admin are told once. Or: tell the uploader to come back tomorrow.
  11. Not enough space in the studio Drive. The decision says "warn". Recommend: before uploading, if the chosen files won't fit, the uploader sees "The studio's storage is nearly full. Some files may not fit. Tell the person who sent you this link." Files that can't fit are held, not started, and the Owner is told. The uploader never sees the studio's numbers. Or: warn only, and start everything anyway.
  12. Small confirmations of numbers the decisions gave as examples: "Uploads look finished" after 10 min with nothing moving; the IP address and device details kept 90 days and then erased (the name and file list stay with the task, as its history); the IP shown to the Owner only.
  13. Files that could be harmful. Every type is accepted (decided), and video is too big for Google to scan for viruses. Recommend: the Admin's list shows each file's full name, and programs or web pages (".exe", ".apk", ".html", ".svg" and similar, or a double name like ".mp4.exe") get a grey Check before opening chip. Nothing is blocked. Or: refuse those types on the upload page.

Already decided (issue #89, 14 Nov), drawn as given

  • One link per task, no login, add-only, no listing, no editing or deleting
  • Lives until the task is done or cancelled, or the Admin stops it
  • Each uploader types their name; it's not checked
  • Someone not on the task is allowed and flagged; the Admin is told once
  • Bytes go browser → Google directly; a few files at a time; chunked and resumable
  • Any file type, any size; warn if the studio Drive would run out
  • Laptop keeps the folder structure; a phone sends files only
  • Per-file progress, overall "8 of 12 done · 3.1 GB of 5.4 GB · about 6 min left"
  • Network lost: resumes by itself; screen lock: warn, resume on return
  • "Keep this page open" banner and a warning on closing the page
  • "I'm done" is optional; the Admin is told for each uploader
  • Stuck after 15 min with no progress: the Admin is told
  • "Uploads look finished" signal to the Admin
  • Admin's "All files received" stops the link; marks Done only through the coordinator path
  • Files owned by the studio account; no copy in MaxOff's storage
1 · Owner and the task's Admin

Getting the link new

  • On the task's Work view, a new Uploads card. Before there is a link it holds one outline button, Get upload link. It never becomes the page's solid button.
  • Once made: the link, Copy link, and a ⋯ with Make a new link and Stop link. Stop is red outline in the menu, kept away from Copy, and confirmed with a named red button.
  • The link is shown only here. It doesn't appear in notifications, chat previews or the task's history.

3 · Anyone with the link · phone

Problems and limits new

  • There is no file-type or size limit (decided). What can still stop a file: the studio running out of space, Google's daily limit, or a file the phone can't read.
  • A stopped link and a mistyped link look the same, and say nothing about the task.
  • A file whose real type looks risky (a program or a web page, for example ".mp4.exe" or ".html") is still accepted, as decided; the Admin's list shows its full name with a grey Check before opening chip (question 13).

5 · Owner and the task's Admin · laptop and app

The Admin's live view on the task new

  • The Uploads card on the task's Work view. One row per uploader: files done / in progress / failed, data sent, last activity.
  • Not on this task · new name marks someone who isn't assigned (grey chip: it's information, not a problem).
  • Stuck (red) after 15 min with no progress, with no call buttons (Q3: the uploader gave a name only). Looks finished (amber: your move) when every started file is done and nothing has moved for 10 min.
  • The card refreshes on its own while anything is uploading (every few seconds), and stops when nothing is.
  • The page's one solid button is All files received (green: a positive final decision, it can mark the task Done).
