1 · The most visible one

Profile photos, done properly

  • Where: beside names in task chat, the task's people, Approvals rows, People, a person's page, the calendar day popup and Alerts. Never inside calendar month boxes or long tables, where they'd add noise.
  • Sizes, fixed: 20 px in list rows, 28 px in chat and Alerts, 40 px in People and headers, 64 px on a person's page and Me. A fine ring separates every photo from the background in both themes.
  • No photo yet: initials on one of four calm MaxOff colours, always the same colour for the same person, so nobody looks "missing".
  • Several people on a task: up to 3 overlapping photos, then "+2".
  • In this mock the "photos" are colour placeholders; real ones are the team's own pictures.
  • Who sees photos: every active team member sees everyone's photo (decided 16 Oct); no other file opens up. A deactivated person's photo stays beside their old messages.

ANRKinitials when no photo
Tiny files

When someone uploads a photo, their phone makes a small 96 px copy (a few KB). Lists only ever load that copy; the larger 512 px one is for the person's own page.

Nothing jumps

Every photo has a fixed size and shows the initials first, so the page never shifts when a photo arrives.

Loads once

Photos are cached by the phone; scrolling back or reopening a screen doesn't download them again. Off-screen photos load only when scrolled to.

No extra database work

The photo link comes with the person's name in the same read, never a separate lookup per row. Covered by the speed gate before release.
