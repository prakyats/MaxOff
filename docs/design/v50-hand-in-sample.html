v5.0 Hand in work: screens to approve

The Crew hand in photos and videos on a task inside MaxOff. Each file goes from their phone or laptop straight into the task's folder in the studio's Google Drive, into a subfolder for each hand-in version (v1, v2…). This is the same way the v4.5 upload link works, and MaxOff keeps no copy. Reviewers see the file list in MaxOff and open the files in Drive. The approval route doesn't change: Mark done goes to the approving Admin, then the Owner. Nothing here is built yet. The example names (Sam, Alex, Jordan, "Brand reel", "Example Café") are made up.

Questions for the owner

The 25 Nov decisions left these six open. The screens below are drawn with the recommendation for each one.

  1. Who can add files to a hand-in? Recommended: everyone on the task, so a second shooter adds their own clips. Only the primary owner taps Mark done, and that hands the version in (invariant 6 is unchanged). A freelancer's coordinator adds files for them. Instead: only the primary owner adds files.
  2. Does Mark done need files? Recommended: no, files are optional. A task with nothing to hand in, like a meeting or a call, is marked done with a note, as today. Instead: a setting on each task type, "needs a hand-in", which blocks Mark done until there's a file.
  3. A wrong file added before handing in. Recommended: Leave out. Before Mark done, the person who added the file (or the primary owner) taps Leave out. The file stays in the Drive folder, because MaxOff never deletes anything. It shows as "Left out" under the version, folded away, and isn't counted. Anyone with the studio Drive can delete it there. Instead: no Leave out, and the reviewer sees every file that was added.
  4. Which files. Recommended: any file of any size (a PDF, a project file, a RAW photo), as with the upload link. Risky types get the grey Check before opening chip. Instead: photos and videos only.
  5. Asking for changes to particular files. Recommended: a reason only, as today. The reviewer names the files in it, and the box suggests doing so. Instead: tick the files that need changes (more screens; it could come later).
  6. Who opens hand-in files in Drive. Recommended: the Owner and the task's Admins: its creator, its approving Admin, and the Admin who coordinates a freelancer primary, the same three as the upload link. They already use the studio Drive account. Everyone else on the task sees names and sizes only. Crew never get a Drive link. Instead: any Admin who can see the task.

Already decided (owner, 25 Nov), drawn as given

  • Hand in photos and videos on the task, inside MaxOff
  • Files go straight into the task's folder in the studio Drive
  • The same browser-to-Drive mechanism as the upload link: chunked, resumable, a few files at a time
  • One subfolder per version (v1, v2…); originals never touched
  • Reviewers see the list in MaxOff and open the files in Drive
  • No copy in MaxOff's storage; no previews made
  • Approval route unchanged: Done → approving Admin → Owner
  • Only the primary owner marks Done
  • MaxOff never deletes a file; "Removed in Drive" when it's gone
1 · Crew on the task · phone, 375 px

Adding files on a phone new

  • A new Hand-in card on the task's Work view, above Stages. It names the version the next Mark done will hand in: v1 at first, v2 after a send-back.
  • Add photos and videos is an outline button. It opens the phone's own picker (gallery or files). The page's one solid button stays Mark done, which is neutral and sticky at the bottom, shown only to the primary owner.
  • Each file goes into Drive as soon as it's chosen. The statuses are Waiting (grey), Uploading (blue), In Drive (green), Failed (red, with Retry) and Already added (grey).
  • Uploads keep going while you move around MaxOff in the same tab. A small pill shows the progress, and tapping it brings you back. Closing the tab asks first.

3 · Crew · phone

When something goes wrong new

  • The network drops: uploads stop and resume on their own from where they stopped. There's nothing to tap.
  • A file fails (it broke on the way, or Google refused it): it's marked red with Retry. It never reaches the reviewer.
  • Leave out (Q3): from a file's ⋯ menu, before Mark done. The file stays in Drive, marked Left out.
  • Coming back after closing MaxOff: choose the files again, and the ones already in Drive are skipped (matched by name and size).

5 · The approving Admin and the Owner · laptop

Reviewing a hand-in new

  • When the task is Submitted (the Admin's step) or Admin approved (the Owner's), the Hand-in card shows the version waiting for you: who handed it in, when, the note, and the files.
  • Open the v2 folder in Drive ↗ and an Open in Drive ↗ link on each file (Q6: the Owner and the task's Admins only). They open in the studio's Drive account, which the Admins already use.
  • Earlier versions are folded below with the reason each was sent back. Left-out files are folded under their version.
  • The buttons don't change: Approve (green) and Request changes (outline).
  • A handed-in file someone deleted in Drive shows Removed in Drive (a grey chip). This is checked after the card is on screen, never slowing the page down.
