## Things the next session must know
- **Function grants (learned in 0.2):** Postgres grants EXECUTE to PUBLIC on every new function, and a per-schema `alter default privileges ... revoke` can't undo it. Every function in `app` and every future `security definer` function needs an explicit `revoke all on function ... from public` + `grant execute ... to authenticated, service_role`, and a pgTAP test that `anon` can't call it. The pgTAP grant tests caught this.
- **Decisions in 0.2 (2026-09-21):** Vitest arrived early so `core/time` and `core/errors` ship with tests; `pnpm test` is in `check`. `db:test` (pgTAP) joins `check` and CI in **0.4**. `.claude/settings.local.json` is git-ignored (personal hooks). ESLint forbids a bare `new Date()` outside `src/core/time/**` and tests (ADR-0008); use `todayIST()` / `systemClock`.
- **Error convention (ARCHITECTURE §4.3):** transition functions call `perform app.fail('INVALID_STATE', 'human reason')`; the message is the code, the detail is shown to the user. `core/errors` maps it; a `P0001` whose message isn't a known code becomes `INTERNAL`.
- **`core/db` entry points:** `@/core/db/server` (RLS, per request), `@/core/db/browser`, `@/core/db/service` (bypasses RLS, jobs only). The index exports types and env readers only, so `server-only` never reaches a browser bundle. Env names: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` (legacy anon / service_role JWTs also work).
- `src/core/db/database.types.ts` is generated by `pnpm db:types`; rerun it after every migration. `@types/node` is now ^24 (Vitest 5 peer).
- **For 1.2 (auth):** `supabase/config.toml` still has the CLI defaults `enable_signup = true` (twice, `[auth]` and `[auth.email]`) and `minimum_password_length = 6`. 1.2 turns sign-ups off and raises the length; `site_url` and redirects already point at `http://localhost:3000`.
