## Ideas / tech debt (don't build these without adding them to the roadmap)
- **Sentry stack traces are not symbolicated on the Worker.** Frames read `worker.js:<line>`: `withSentryConfig` uploads (and deletes) source maps for Next's chunks during `next build`, but OpenNext then re-bundles them into `.open-next/worker.js` without a map, and that file's debug id matches nothing uploaded. Fix in a deploy-workflow task: keep Next's maps (`deleteSourcemapsAfterUpload: false`), build the Worker with a source map (check `opennextjs-cloudflare build` / esbuild options), then `sentry-cli sourcemaps inject` + `upload` on `.open-next/` with the release set to the commit SHA, and delete the maps before `wrangler deploy`.
- **Sentry infers a geo country from the connecting IP** even with IP storage off (server events show the Worker's egress country; browser events from 0.5's client SDK would show a member's). Decide in 1.2 whether to strip `user.geo` in `scrubEvent` (one line) or accept country-level data. Also cosmetic: `server_name: localhost` on Worker events.
- **Service worker + auth (1.2):** `refreshOfflinePage()` in `public/sw.js` caches whatever `/offline` returns while `response.ok`; after 1.2 a redirect to `/login` would be followed and cached as the offline page. Guard with `!response.redirected && new URL(response.url).pathname === OFFLINE_URL` and keep `/offline` outside the auth guard.
- **CI runs twice per PR push** (`push: phase-*` plus `pull_request`, different concurrency keys). Drop the `phase-*` push trigger now that branch protection requires the PR checks, or skip the push run when a PR exists.
- **`package.json` `engines.node` is `>=20.9.0`** while CI, deploy, `@types/node` and Vitest 5 assume Node 24. Raise to `>=24` so a wrong Node fails at install, not at `pnpm test`.
- **Tags:** `git push --follow-tags` pushes only *annotated* tags, and `git push origin phase-N` is ambiguous (branch and tag share the name). Push phase tags as `git push origin refs/tags/phase-N`.
