# MaxOff Roadmap (v2)

> **PRODUCTION IS LIVE (since 2026-10-01): `https://app.maxoff.in` is in daily use by the Pixora Clips team with real data.** Expand-only migrations, releases only by an Owner-approved `v*` tag on a green `main` commit, never a seed, reset or hand-written SQL on production. The rules are in `CLAUDE.md` → "Production is live".

> **One unit = one Claude Code session** (or one step of `/run-phase`). From phase 3 each phase lists its **units** (process change 2026-09-26, owner decision): a unit groups the tasks one session builds together, its tier is the highest of its tasks, and 3A and 6A are the heavy ones (`/save-progress` at ~50% context is the release valve). Tick a task (`[x]`) only when the Definition of Done (CLAUDE.md) is met and it's committed; a unit is done when every task in it is.
> Before a phase: `/kickoff-phase N` settles every business question it raises, at once. Then `/run-phase N` (one subagent per unit, in order) or `/start-task <unit>` one unit at a time.
> Each phase ends with `/review-phase N` (review → fixes → merge to `main` → tag `phase-N-done`; the branch stays `phase-N`).
> **Model tier** per task (mapped to actual models in BUILD-GUIDE.md):
> **[H]** highest-capability model: schema, security, transition functions, jobs, reviews · **[C]** strong coding model: features and UI · **[Q]** fast model: polish and docs.
>
> **Launch order (owner decision 2026-09-28: staff first, staged).** Work strictly in this order. **No stage waits for a calendar date**: the next phase starts as soon as the previous one is reviewed and merged, and each stage is released to production at once, so the team uses it the same day.
> 1. **3b** review → merge.
> 2. **3c Go live → stage 1 is live in production:** attendance, leave, comp leave, expense claims, the month summary, clients and people. Staff tasks keep running outside MaxOff until stage 2.
> 3. **4** Staff tasks, with freelancers → released.
> 4. **5** Notifications and reminders → released.
> 5. **6** My Day, the Owner's Today, the Admin dashboard, the calendar, the end-of-day report, production hardening → released.
> 6. **8** Work submissions (before 7: handing in work hangs off tasks, not projects) → released.
> 7. **7** Client projects (Owner and Admin tracking; staff never use it) → released.
> 8. **9** Revenue, reports and month close (Owner) → released.
> 9. **10** Polish, the security review, performance, full launch.
> Then "Deferred past the launch". If work has to slip, staff-facing phases (4, 5, 6, 8) go first and the Owner-only ones (7, 9) wait.
> **From stage 1 on, production holds real data:** every phase is released with a tag after its review; migrations stay **expand-only across a release** (the running code must keep working against the new schema while a release rolls out), and destructive changes ship in a later release. Five tasks are **deferred past the launch** (section at the end).
